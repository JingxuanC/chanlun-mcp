## P1 · 文档与代码不一致（会固化进 MCP 接口，必须先定口径）

1. **卖出判定频率**
   - 文档 §4.4/§7.1：每根 60min bar 收盘判定。
   - 代码 `backtest_portfolio.py:525-568`：每个交易日最后一根 bar 收盘判一次（源码注释自认"简化为每日一次"）。
   - 影响：策略实际是"60min 入场 + 日频出场"；改成 bar 级出场后回测结果会变，尚未测。
   - 处置：先按代码 parity 移植，另开 `ExitCheckMode::Every60MinBar` 做对照回测。

2. **包含关系合并方向**
   - 文档 §4.1：按"当前笔方向"取高高/低低。
   - 代码 `chanlun.py:775-809`：按最后一根合并 K 线阴阳的启发式（且有一行重复赋值）。
   - 处置：先 parity；后续加 `merge_direction_mode=strict_bi` 开关并对比信号差异。

3. **"无未来函数"的论证不完整**
   - §10.1 用"买入价 = 当日某根 bar 开盘价"证明无未来函数——这只证明执行价无前视，不证明信号计算无未来数据。
   - 真正干净的是 `g+4` 截断重算 + `g+5` 开盘买入；移植时以这个时序为准，并补信号级 golden test。

4. **"样本外（2025 年起）"不是真 OOS**
   - 两个过滤因子是 2026-08-04 用全样本选的（§4.5），2025+ 落在选参区间内。
   - 处置：MCP 里不要把这个数字当 OOS 卖点；需要时补真正的 holdout 折表。

## 追加（2026-11-19）：真实数据 G-2 暴露并修复的 parity bug

**numpy float32 均值精度**：Python 参考实现的 OHLCV 被 `downcast` 成 float32，MA13 用
`df["close"].mean()`；numpy 对 float32 走 **pairwise 求和（8 累加器）**，与"转 f64 再平均"
在 1 ulp 量级上不同。在 close 恰好与均线相差 1 ulp 的 bar 上会翻转 `<` 判定：

- 600158 在 2021-07-16：`close=11.762499809265137`
  - numpy f32 mean = `11.762500762939453` → `close < ma13` = **true**（Python 次日卖出）
  - f64 平均再转 f32 = `11.762499809265137` → **false**（Rust 曾因此晚卖一天）

修复：`crates/chanlun-engine/src/precision.rs` 逐位复刻 numpy `pairwise_sum` 与 f32 除法，
MA13 退出（`simulate.rs`）与 Phase B 入场乖离（`signals.rs`）都改用该实现。
修复后 72 只真实票 legacy/dynpos G-2 均逐笔一致、nav 偏差 <1e-15。
